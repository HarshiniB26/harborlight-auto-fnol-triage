# Security

IAM and application authorization are separate. The instance role controls
which AWS APIs the process can call. Handler sessions control who can prepare
a draft, submit a review, or file an already approved record. Neither one can
approve a review. Approval stays on the runtime CLI.

## Network

- The instance security group allows TCP 443, and TCP 80 when `AllowHttp` is
  true, from `AllowedCidr` only.
- Ports 22, 5432, 8080, and 8767 are not open to the internet. The container
  publishes `127.0.0.1:8080` only.
- The database security group allows TCP 5432 from the instance security group.
  `PubliclyAccessible` is false. The database subnets have no route to the
  internet.
- Instance egress is TCP 443 to the internet, DNS to the VPC CIDR, and TCP
  5432 to the database security group.
- IMDSv2 is required. The hop limit is 2 so the container can use the instance
  role without a stored access key.

The default `AllowedCidr` is the documentation range `203.0.113.10/32`. Replace
it. A wide CIDR makes the HTTP site reachable before the certificate exists.

## IAM

The instance role has two AWS managed policies and one inline policy.

`AmazonSSMManagedInstanceCore` is attached so Session Manager can open a shell
without port 22. It is the policy AWS documents for that agent. It does not
grant S3 or database access.

`CloudWatchAgentServerPolicy` is attached so the CloudWatch agent can publish
host logs and metrics. Application log writes are also granted inline, limited
to the FNOL log group.

Inline grants:

- `s3:GetObject` on the dataset object ARN and on
  `releases/fnol-app.tar.gz` only. The release object exists because the
  instance has no SSH, registry, or load balancer to receive a build. The
  dataset upload uses the operator's credentials, not this role.
- `secretsmanager:GetSecretValue` on the RDS master secret, the application
  role secret, and the auth secret.
- `logs:CreateLogStream`, `logs:PutLogEvents`, and `logs:DescribeLogStreams`
  on the application log group.
- `bedrock:InvokeModel` only when `EnableBedrock` is true, and only on the
  configured model or inference-profile ARN. The default stack omits this
  statement.

There is no `s3:*`, no `iam:*`, and no account-administrator policy.

## Data

- The bucket blocks public ACLs and public policies, enforces bucket-owner
  object ownership, versions objects, and defaults to SSE-S3.
- The bucket policy denies requests that are not TLS.
- Noncurrent versions expire after 30 days. The bucket is retained when the
  stack is deleted so a stack rollback does not destroy the dataset. Empty it
  by hand before deleting a development bucket.
- RDS storage is encrypted. Automated backups are on. Deletion protection is
  on only for `Environment=prod`. A stack delete snapshots the database.
- The master password is generated by RDS into Secrets Manager. The
  application password is a separate generated secret. CloudFormation outputs
  the ARNs, not the values. User data does not contain either secret.
- `fnol_app` can read and write the FNOL tables. It is not used to create
  schema. Migration uses the master secret.

## Application auth

`FNOL_AUTH_REQUIRED` defaults to false so the local tests and the current
training UI keep working. Production `scripts/deploy-app.sh` sets it to true
and refuses to deploy if the auth secret has no users. The workbench then
requires an HttpOnly session cookie. A missing or empty user directory fails
closed.

Roles are `handler` and `reviewer`. Both may use the workbench API. The
workbench still has no approve method. When auth is required, the CLI rejects
a `--reviewer` value that is not a configured reviewer.

Passwords are not written to the structured logs. Dataset `private_token`
values are still stripped before a draft is built.

## Bedrock

The model client is disabled by default and is not imported by the routing or
citation code. When it is enabled, the prompt contains the case id,
classification, and route. It does not contain document text. Timeouts and API
errors become a warning. They do not change the draft, the hash, or the
approval rule.

## Alarms

CloudWatch alarms cover the EC2 status check, RDS CPU, free storage, and
connection count, plus a metric filter for `runtime_unavailable`. They do not
page an email or chat system. Add an alarm action if an operator must be woken
up. That keeps the small deployment off extra notification services until you
need them.

## Residual risks

- One instance is a single failure domain. An Availability Zone outage takes
  the site down until the instance is replaced. The database can be Multi-AZ
  later; the template defaults to one zone.
- HTTP is exposed to `AllowedCidr` until Certbot is finished. Do not put a
  wide CIDR in the parameter.
- Sessions live in process memory. A restart signs everyone out.
- The instance role can read the master database secret because migrations run
  on the same instance. A person with a Session Manager shell can retrieve it.
  Restrict who may start a session.
- The CloudWatch agent policy is broader than the inline log-group statement.
  It is limited to agent operations, not to arbitrary AWS services.
- Alarms have no notification target until you add one.
- Bedrock output is untrusted text. The UI shows it as a warning. It is not a
  coverage decision.
